# Competition demo and evidence collection

The [feature guide](FEATURES.md) includes a demonstration for every capability, including access, storage deletion and configuration-only controls. The app’s `/demo.html` gives a short presenter checklist. Use a disposable dedicated workspace with synthetic files.

## Automated runtime demonstration

Start the configured service on the prepared Linux VM. In the runner environment, set SAFECODE_URL, SAFECODE_ACCESS_TOKEN_FILE and SAFECODE_TRUSTED_PUBLIC_KEY_FILE. The trusted public key should come from the operator through a separate authenticated channel.

```bash
npm run demo -- --competition
```

The competition profile requires runsc, live Vultr inference, authentication and signing. The runner saves actual JSON receipts and `data/demo-evidence/report.json`, exits nonzero on any failed scenario and never simulates successful runtime evidence. It checks CSV fixture totals, charts, signatures/tampering, distinct receipts, self-healing, every preset, spoofed error labels, cancellation, budgets/dashboard and pause. It restores pause after its own pause test and does not delete stored data. Run it only where other users' jobs will not be interrupted.

For a local Linux mock demonstration, omit `--competition` and set SAFECODE_FORCE_MOCK=1 on the server. This is not live inference evidence. With no sandbox, preflight fails rather than executing on the host.

## Three-minute main recording

- 0:00–0:20: problem: AI teams want to ship customer-file analysis with controlled execution and reviewable evidence. Show actual runtime/provider/signing/access state; keep credentials off camera.
- 0:20–0:55: upload `docs/demo-sales.csv`, inspect generated code, run it, compare north=320/south=80/east=50 to the fixture. Show sandbox chart and reported results.
- 0:55–1:20: self-heal preset; show initial failure, model repair, new sandbox ID and per-attempt source/model record. State that enabling retries approves those subsequent automatic executions.
- 1:20–1:50: network preset and infinite loop. The network preset connects to a numeric address because a hostname lookup can sit until the wall-clock timeout. Show that network denial is inferred from the error text, and that the loop's timeout is controller-observed. Rerun the normal task to demonstrate continued service operation.
- 1:50–2:15: download receipt, run verifier, alter a copy and show rejection. Explain issuer integrity versus execution truth.
- 2:15–2:40: cancel a running loop; pause execution; show the rejected new run and usage counters; resume.
- 2:40–3:00: who it helps: AI product teams running generated code over files. State independent adversarial assessment and shared-tenant validation remain future gates. Link repository and actual deployed URL.

Do not promise that all program answers are correct or escapes impossible. Do not call these presets independent penetration testing. If a feature fails, fix it or report it accurately.

## Optional browser captures

Existing PNGs are historical v0.2 screenshots. To create new v0.3 evidence on an available browser/runtime host, install Playwright and its Chromium, provide the token file if needed, then run:

```bash
python3 scripts/e2e.py https://your-demo-host
python3 scripts/e2e_features.py https://your-demo-host
```

These scripts use a separate browser context and produce screenshots, not a narrated video. Check screenshot contents before publishing; receipts can contain prompts, source and outputs. No new browser recording has been generated by the portable test run.
